# Build, run, and deploy

## Requirements

- Node.js 20+ (built and tested on Node 22).
- No database. One optional environment variable, `GEMINI_API_KEY`, used only by the chat widget
  (see "Optional: the chat widget" below). Everything else is static (`architecture.md` §3) and
  builds and runs with no configuration at all.

## Optional: the chat widget

The "Ask about Hariank" widget calls `/api/chat`, which proxies to the Gemini API. It is the only
part of the site that needs configuration, and the only non-static route.

- Get a free key at https://aistudio.google.com/apikey.
- Locally: copy `.env.local.example` to `.env.local` and fill in `GEMINI_API_KEY`.
- On Vercel: add `GEMINI_API_KEY` under the project's Environment Variables.

Without a key the site builds and runs normally — the widget just returns a "chat is not
configured" message instead of answering. The model is pinned in `src/app/api/chat/route.ts`;
Google renames free-tier models periodically, so that constant is the one thing to check if the
endpoint starts 502-ing.

## Local development

```bash
npm install
npm run dev
```

Open `http://localhost:3000`.

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Dev server with hot reload (Turbopack, Next 16 default) |
| `npm run build` | Production build. Runs the full TypeScript check as part of the build — a type error fails the build, not just `next dev`'s overlay. |
| `npm run start` | Serves the production build from `.next/` — run `build` first |
| `npm run lint` | ESLint (flat config, `eslint.config.mjs`, extends `eslint-config-next`) |

There is no separate `typecheck` script; `npm run build` covers it. Running raw `tsc --noEmit`
before a build exists will fail on `LayoutProps` (a Next.js-generated global type that only exists
after `.next/types` has been generated by a build/dev run) — that's expected, not a bug.

## What was actually verified during the build

- `npm run build` — clean, zero errors, all 12 routes generated (see `architecture.md` §3 for the
  route list: `/`, 4× `/work/[slug]`, sitemap, robots, icon, apple-icon, opengraph-image, and the
  per-project opengraph-image).
- `npm run lint` — zero errors. One real issue was caught and fixed here: `ThemeToggle`'s original
  `useEffect` + `setState` mount-detection pattern tripped `react-hooks/set-state-in-effect`; it
  was rewritten with `useSyncExternalStore` (see `architecture.md` §6).
- An axe-core accessibility scan (Playwright + `@axe-core/playwright`, run ad hoc — not committed
  as a project dependency, see below) against `/`, both flagship case studies, in both themes.
  Caught two real WCAG AA contrast failures, both fixed in `globals.css`:
  `--fg-faint` (was 3.4:1 against the dark/light backgrounds, now ≥4.9:1) and the light-mode
  `--accent` (was 4.07:1 as button text on `--accent-fg`, now 4.8:1).
- Manual visual QA at desktop (1440px), tablet (834px), and mobile (390px) viewports, in both
  themes, via Playwright screenshots.
- Two real functional bugs were caught this way and fixed:
  1. **Mobile nav clipped to the header height** — root-caused to `backdrop-blur` on `SiteHeader`
     establishing a containing block for the dialog's `position: fixed`. Fixed by portaling the
     dialog to `document.body` (`components/layout/mobile-nav.tsx`) — see `architecture.md` §8.
  2. **Reduced-motion fallback dropped styling, not just animation** — `RevealText`'s
     `prefers-reduced-motion` branch rendered plain text without the `wordClassName` (the hero
     tagline's italic treatment). Fixed in `components/ui/reveal.tsx`.
- Fonts confirmed fully self-hosted (see `architecture.md` §5) — verified with `curl` that the
  build environment could reach `registry.npmjs.org` but not `fonts.googleapis.com`, which is why
  `next/font/google` was replaced with the `geist` + `@fontsource-variable/fraunces` packages.

`@axe-core/playwright` and `playwright` were used as one-off testing tools during the build and
are **not** in `package.json` — they were installed, used, then uninstalled again to keep the
shipped dependency list minimal (per the "avoid unnecessary dependencies" project brief). Re-add
them (`npm i -D @axe-core/playwright playwright`) if you want to re-run that scan later.

## Deployment

Any Next.js host works; Vercel is the natural fit given the stack. Steps:

1. Update `SITE_URL` in `src/lib/constants.ts` to the real production domain — it feeds canonical
   URLs, Open Graph tags, JSON-LD, and `sitemap.ts`.
2. `npm run build` — confirm it's still clean.
3. Deploy the standard way for your host (for Vercel: connect the repo, no config needed — no env
   vars, no build command overrides required).
4. No cron jobs, background workers, or database migrations — nothing else to configure.

## Updating the résumé

Replace `public/resume/hariank-juneja-resume.pdf` with a new file **of the same name**, or change
`profile.resume.href` in `src/content/profile.ts` if you want a different filename. No component
changes needed either way.
